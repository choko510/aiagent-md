# Local Device Client: implementation audit

Baseline: `53ac14c5376509cef0293ed236bd417a6c8d2f6e` (origin/main). This is an implementation audit, not a specification lock or production approval.

- The existing `TlsAuthenticatedChannel` accepted caller-supplied handshake and client-certificate booleans. No TLS handshake, certificate validation, device proof of possession, or signed server permit was performed. The placeholder now refuses pairing and never reports online or issues a permit. The legacy fields remain solely for compatibility pending replacement by a real transport.
- The former `LocalAdapters` reported success on flags or the existence of a directory and invoked `adb` through PATH. None proved the requested OS, browser, build or Android operation occurred. These adapters now return failure and launch no process. Simulator `MockAdapters` remain separate and do not establish native behavior.
- The simulator journal writes its control envelope as `enc:v2` using XChaCha20-Poly1305 and HKDF-SHA256 with a scope/label-bound context and random 192-bit nonce. Read-only legacy `enc:v1` authentication and decryption are retained for migration; an atomic compare-and-swap update seals the verified control record and flags together. Legacy audit-only records migrate to stopped, with revocation retained; a recovery marker cannot be reused to clear a subsequent Stop. A failed migration fails closed; a missing key for an existing database or a missing database for an existing key is not silently replaced. Normal saves cannot clear an already persisted Stop or Revoke, including from a stale process. A downgraded old client cannot read the new format, so rollback requires a separately managed backup and must not restore stale authority. The format migration does not detect deletion of both files or rollback. Only the control envelope is sealed: other metadata is visible, Unix stores its master key in a plaintext mode-restricted file, and the master key is shared across journal scopes. A production key store, per-identity key lifecycle and authenticated whole-journal design remain required.
- Cryptographic implementation: RustCrypto `chacha20poly1305` 0.10.1 and `hkdf` 0.12.4, pinned in Cargo.lock (MIT/Apache-2.0). See the [AEAD crate documentation](https://docs.rs/chacha20poly1305/0.10.1/chacha20poly1305/) and [HKDF crate documentation](https://docs.rs/hkdf/0.12.4/hkdf/). The random extended nonce avoids requiring a shared counter across processes; it does not provide rollback protection.
- `device-transport` provides an outbound WSS socket using rustls and public WebPKI roots, with certificate-chain and hostname checks, bounded frames, connection/I/O timeouts and closure after failed or cancelled I/O. URL credentials, query strings, fragments and plaintext connections are rejected. Its private test helper accepts an ephemeral test certificate; the production API does not accept a test CA or a custom verifier. Loopback tests perform actual TLS and WebSocket handshakes, including bad certificate, hostname mismatch, oversize message and cancellation cases. This is **server authentication only**: no device proof of possession, pairing, signed messages, heartbeat, connection generation, private self-hosted CA configuration or Gateway integration exists yet. The transport does not implement `AuthenticatedChannelPort` or enable operations. Selection is provisional: rustls 0.23 / ring, tokio-tungstenite 0.28 and WebPKI roots are fixed by Cargo.lock; see [rustls](https://docs.rs/rustls/0.23.46/rustls/) and [tokio-tungstenite](https://docs.rs/tokio-tungstenite/0.28.0/tokio_tungstenite/) documentation. Device signatures and wire contracts remain undecided.
- Tauri and agent currently share a process; there is no authenticated owner-bound IPC. Pairing, signed grants, online start authorization, device gateway, semantic effect barrier, historical receipt reconciliation, native adapters and production isolation remain unimplemented. A mock `START_PERMIT` is not evidence of cloud authorization.
- PR #122 is open and reserves migration 0029; its changes include Tool Gateway, Sentinel, API and development integration. This slice adds no database migration or shared backend change. Separate integration and current merge-order verification are required.

Tests of the mock state machine are partial LDC coverage, not LDC-T01 through LDC-T32 acceptance. TLS/WSS has only the local server-verification tests described above, not authenticated Device/Gateway integration. Real device I/O, GUI, Android, production VM isolation, performance and end-to-end tests remain NOT RUN. Features must remain disabled until their individual security and acceptance gates are implemented and verified.
