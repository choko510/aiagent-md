# 書き方メモを作る

ユーザーの文体・言い回しの好みを記録した「書き方メモ（`~/.nihongo/profile.md`）」を作り、本人名義の文（LINE・メール・SNS・ESなど）に活かすための手順。

## 基本設計（4つの箱＋Anti-Voice）

既定の保存先は **`~/.nihongo/profile.md`** とする。どの git リポジトリの外にも置くことで、スキルの更新で消えず、誤って push する心配もない（すでに `CLAUDE.md` や `AGENTS.md` などに「私の書き方」メモがある場合は、引き続きそちらも尊重する）。

メモは **`[common]` / `[casual]` / `[work]` / `[formal]` の4つの箱** で管理する。

- **Anti-Voice（`絶対に言わない表現`）**：自分らしさを出す一番の近道は「使いたい言葉」を増やすことより、「絶対に言わない表現」（例：過剰な敬語「〜させていただきます」、カタカナ語、絵文字の連打など）を `[common]` に並べること。ここに書いた表現は執筆時の基準になるだけでなく、`cli.py diff` / `cli.py git --profile ~/.nihongo/profile.md` で機械的にもチェックできる。
- **場面の境界（フェイルセーフ）**：敬語の高さ・定型・崩してよいかは相手と場面で先に決め、プロフィールはその枠内でのみ使う。**`[casual]` の崩しや絵文字は `[formal]` へ絶対に持ち込まない。** 相手や場面が曖昧な時は、必ず安全な側（`[work]` または `[formal]`）へ倒す。
- **透明な1行学習（黙って書かない）**：ファイルへ黙って書き込むことはしない。ユーザーはいつでも「書き方メモ見せて」「`[casual]` の〇〇消して」で中身を確認・削除できる。
- **個人情報禁止**：実名・会社名・メールアドレス・電話番号などの個人情報・固有名詞は絶対に書かない。

## 標準フォーマット（`~/.nihongo/profile.md`）

見出し（`## [common]` / `## [casual]` / `## [work]` / `## [formal]`）と `- 絶対に言わない表現：` 行は `cli.py --profile` でも解析するため、見出し名と項目名は変えずに使う。

```markdown
# 私の書き方

## [common]
- 一人称：
- 絶対に言わない表現：
- 書く時の考え方：

## [casual]
- 場面：友達・身内・雑談
- 口調・記号：

## [work]
- 場面：社内チャット・PR・同僚
- 口調・記号：

## [formal]
- 場面：目上・社外メール・公式お知らせ（[casual] の崩しや絵文字は持ち込まない）
- 口調・記号：
```

## ゼロ摩擦の始め方

始め方は3通りから選ぶ。事前設定を強制しない。

### 方法A：会話学習（既定・0秒開始）

- 事前準備なしで普段どおり使い始める。
- ユーザーが口調・語尾・言い回しを明示的に直した時、または同じクセが2回出た時だけ、返答の末尾に1行で1回だけ聞く。
- **必ず「入れる箱」と「足す1行の内容」を両方示す**（例：`「〜ですね」より「〜だね」寄りにしてるけど、[casual] に1行足しておく？（[formal] には使わないよ）`）。
- **黙って書き換えない。** OKをもらってから `~/.nihongo/profile.md` の該当の箱に1行だけ追記する（ファイルが無ければ標準フォーマットで作る）。
- 直した例は貼った文より確かな材料として扱う。直しから考え方を推測せず、本人が直した形のまま記録する。実名・会社名・メールアドレス・電話番号などの個人情報は絶対に書かない。
- 閲覧・削除を求められたら（「書き方メモ見せて」「`[casual]` の〇〇消して」）、その場でそのまま見せ、指示された行だけを消す。

### 方法B：3問クイック作成（15秒）またはプリセット

すぐ土台を作りたい時は、次の3問に答えるか、3つのプリセットから1つ選んでもらって標準フォーマットの `~/.nihongo/profile.md` を作成する。

- **3問クイック作成**
  1. 一人称（私／僕／自分など）
  2. 絶対に言わない表現（例：過剰な敬語「〜させていただきます」、カタカナ語、絵文字連打）
  3. 普段の口調と距離感（`[casual]` / `[work]` / `[formal]` それぞれの雰囲気）
- **3つのプリセット（4箱形式で出力）**
  1. **フラットな開発チーム敬語**：`[common]` 一人称「私」（または「自分」）、絶対に言わない表現「〜させていただきます」「恐れ入りますが」、結論先出し・短文／`[work]` フラットなです・ます／`[formal]` 標準的な敬語。
  2. **簡潔なビジネス敬語**：`[common]` 一人称「私」、前置き短め・要点先行・余計なクッション言葉を省く／`[work]` 簡潔なです・ます／`[formal]` 標準的な敬語（過度なへりくだりなし）。
  3. **やわらかい口語**：`[common]` 一人称「私／僕」など希望に合わせる／`[casual]` 親しみやすい話し言葉／`[work]` やわらかい「です・ます」／`[formal]` 標準的な敬語（`[casual]` の崩しは持ち込まない）。

### 方法C：過去の文（3〜5通）から詳しく分析する

ユーザーが自分の書いた文を貼って「私の書き方を覚えて」「この感じで書いて」と頼んだ時は、次の手順で分析し、標準フォーマットの4箱へまとめる。見える特徴だけを写すとモノマネになるため、「どう考えて書く人か」を先に読んで `[common]` の「書く時の考え方」にまとめ、場面ごとの口調・記号は `[casual]` / `[work]` / `[formal]` に分けて置く。

#### 分析の手順

1. **貼られた文を3つの箱へ振り分ける**
   - 友達へのLINE・身内・雑談・友達グループのお知らせ → `[casual]`
   - 社内チャット・PR・同僚・実務連絡 → `[work]`
   - 先生・目上・お店・社外メール・公式お知らせ・外向け告知（X、不特定向け投稿） → `[formal]`
   - 場面はユーザーが添えた言葉（「これは告知」）を一番に使い、無ければ宛名・敬語の高さ・出す場所から決める。曖昧な時は安全な側（`[work]` または `[formal]`）へ倒す。README・仕様書・設計書のような技術文書は型と用語の決まりが強いので、貼られても材料にしない（ユーザーが頼んだ時だけ使う）。
2. **文ごとに何を選んだかを読む**
   - 用件を先に言ったか、お礼やお詫びを入れたか、気持ちを言葉で言ったか記号で出したか、言い切ったかぼかしたか、断る時に理由を先に言ったか、相手をどう呼び敬語をどの段にしたかを見る。
   - `[casual]` と `[formal]` の差は、相手との距離の取り方の一番の材料になる。
3. **`[common]` を書く**
   - **一人称**：1通でも読み取れたら書く（場面で変わる場合は `[casual]` 等に補足する）。
   - **絶対に言わない表現**：本人が明示したNG表現や直した表現は1回でも書く（推測で足さない）。
   - **書く時の考え方**：2通以上で同じ選び方が見えたものだけを書く（場面が違う2通でもよい）。1通だけで見えた選び方や、nihongo がふだんする選び方（用件を先に言う、お礼を言う）と同じ物は書かない。
     - 見る観点：先に言うこと／相手との距離の取り方／気持ちの出し方／言い切り方／お願いと断りの仕方／避けること
4. **`[casual]` / `[work]` / `[formal]` の「口調・記号」を書く**
   - 文末（です・ます／常体）は1通でも書く。
   - 長さと改行、語尾、よく使う言葉、言い換えない言葉、記号と絵文字、書き出しと締めは、**2通以上に出た時だけ**「どんな時に出るか」と一緒に書く（「👍は了解の返事の時」「！は誘う文の時」）。本人が「いつも使う」と言った物は1通でも書く。
   - 記号と絵文字は「どんな時」に加えて1通あたりの量の目安も書く（「絵文字は1通に2〜3個、文末と気持ちの文に」）。
   - 方言（関西弁など）は条件付きのクセではなく、その箱の文末と言葉の土台として書く（`[formal]` の決まりはそのまま）。
   - 言葉の例は「」で囲み、説明文に溶かさない（「お疲れさまです」で始める）。
   - 目上への定型挨拶（「何卒よろしくお願い申し上げます」など）は場面の判断で入るのでメモには要らない。
5. **点検する**
   - メモの各行を貼った文に無い場面（目上へのお詫び、公式お知らせなど）に当ててみて、失礼・作り話・モノマネになる行は消すか条件を付ける。
   - 目上・お店・先生・外向け告知（`[formal]`）では崩さない（「っす」「w」不可。絵文字はその場面に2通以上あるか本人明示時のみ。特定の目上あての絵文字・「！」は他の `[formal]` 場面へ流用しない）。
   - 下の「書いてはいけない物」に当たる行をすべて消す。
6. **必要なら末尾に `## 手本` を添える（任意）**
   - 方法Cで実物から作った場合、見た目の参考（名乗り・句点の有無・改行・記号の位置）として場面ごとに1〜2通だけ末尾に `## 手本` を置いてよい。
   - 実名・会社名・出来事・予定・場所・数字・連絡先は必ず【　】に伏せ、名乗りは「【名前】です」の形にする。中身と言い回しは写さない。
7. **確認して保存する**
   - 作成したメモは自然な日本語で書き（この資料内のメタ語「欄・段・材料」は使わず、見出しに句読点を付けない）、ユーザーに見せて「違う所があれば直してください。`~/.nihongo/profile.md` に保存してもよいですか？」と確認する。3通より少ない時は元にした通数を書き、もっと貼ると精度が上がる旨を1文だけ添える。

## 書いてはいけない物

- 実名・会社名・メールアドレス・電話番号などの個人情報・固有名詞
- 貼った文の中身（人名、出来事、予定、場所、数字）。手本では【　】に伏せる
- 人物像の推測（性格、価値観、年齢、性別、仕事、人間関係）。「どう書くか」で書き、「どんな人か」にしない
- 1通にしか出ない語尾・口ぐせ・定型（本人が明示したものを除く）
- 回数だけで書いたクセ（「！を毎文に付ける」）
- `[formal]` で敬語を下げる指示や、`[casual]` の崩し（`〜っす`、`w` 等）

悪いメモと、直したメモの例（架空の合成例）：

```markdown
## [common]
- 一人称：自分
- 書く時の考え方：明るくて気配りができる人。用件を先に言う。毎文に「！」を付ける

## [formal]
- 場面：バイト先の店長へのLINE（1通をもとに）
- 口調・記号：「〜っす」。「来週土曜のシフト」
```

この例には、性格の推測、誰でもする選び方（用件を先に言う）、回数だけのクセ、1通だけの語尾で目上への敬語を崩す指示、貼った文の中身（シフトの日）が入っている。直すと次のようになる。

```markdown
# 私の書き方

## [common]
- 一人称：自分
- 絶対に言わない表現：「〜させていただきます」
- 書く時の考え方：お礼から入り、用件は2文目に書く。断る時は理由を1つ先に言い、代わりの日を出す

## [casual]
- 場面：友達・身内・雑談
- 口調・記号：常体寄り。誘う文や嬉しい時だけ「！」を1つ付ける

## [work]
- 場面：社内チャット・PR・同僚
- 口調・記号：フラットな「です・ます」。了解は「了解です」と短く返す

## [formal]
- 場面：目上・社外メール・公式お知らせ（[casual] の崩しや絵文字は持ち込まない）
- 口調・記号：標準的な「です・ます」。気持ちは記号ではなく言葉で伝える
```

## 適用ルールと置き場所

- **適用範囲**：本人名義の文（LINE・メール・SNS・ES・作文・ブログ等）だけで使う。技術文書と AI 自身の返答には使わない。「メモなしで」と言われたら使わない。
- **優先順位**：`[common]` の `絶対に言わない表現` と `書く時の考え方` は全場面で使うが、相手と場面で決めた敬語の高さと事実保持（捏造ゼロ）は絶対に超えない。
- **置き場所**：
  - **既定（推奨・全環境共通）**：`~/.nihongo/profile.md`（全体の目安：各箱2〜4行、合計300〜600字ほどに収める）
  - すでに設定ファイルで管理している場合：`~/.claude/CLAUDE.md`、`AGENTS.md`、またはアプリの設定欄もそのまま尊重する（希望があれば `~/.nihongo/profile.md` へ移行してよい）。
- **更新の仕方**：ファイルを書ける環境では必ず確認を取り、OK なら `~/.nihongo/profile.md` に反映する。すでにファイルがある場合は既存の `絶対に言わない表現` や各箱の指定を消さずに追記・更新する。書けない環境では、メモ本文と置き場所（`~/.nihongo/profile.md`）を1行で返す。
