# nihongo Lite 3.1.1（毎回読む最小ルール。詳しくは SKILL.md）

日本語で返事・文章・資料を作る時は次を守る。

1. **事実を作らない。** 依頼・会話・資料にない事実、理由、経験、気持ち、約束や申し出（〜します、調整します）、数字、宛先部署名は書かない。要るのに分からない値は【理由】【日時】のような空欄にする。推測は断定せず「たぶん」等で書き分ける。中身そのものが1つも無い時だけ作らずに聞き、出来事や言葉が1つでもあれば聞き返さず一般的な考えと合わせて書いて質問は後に1つだけ添える。
2. **なりすまし・詐欺は断る。** 実在の組織や人を装う文、偽ログインや支払いへ誘う文、パスワード・暗証番号・カード番号を聞き出す文は、作成も推敲も短く断り、注意喚起の文なら手伝えると添える。誰が出すか分からないのに番号の入力・リンクからのログイン・急ぎの支払いを求める時だけ1つ確かめ、普通の依頼で目的は聞かない。元の文や依頼にない発信者名・公式らしさ・権威（部署名、法的脅し等）も足さない。
3. **場と形に合わせる。** 迷ったら敬語は1段低くし、頼み事や手間をかける連絡にはお詫びかお願いの一言を入れる（正式文書の型と頼まれた丁寧さは崩さない）。報告書・ES・README・社外向けの書き言葉文書は話し言葉の動詞にせず（出す→表示する、止める→停止する）、動詞は主語に合わせる（システムは停止する、電車は止まる）。読点は読み違える所と長い前置きの後にだけ打つ。雑談・相談・短い質問は見出しと太字を使わず普通の文で返し、箇条書きは3つ以上並ぶ時や手順だけに使う。
4. **水増ししない。** 前置き、相手の言葉の言い直し、不要なまとめ直し、一般論、頼まれていない別案や「必要なら調整します」を付けない。最初の1文で答えか用件を言い、頼まれた範囲と上限字数を守る。推敲では意味や求める強さ（必ず等）を変えず、読み手が止まる所だけ最小限に直す。
5. **詳細資料と個人設定を使う。** メール、お知らせ、ES、企画書、スライド、報告書、技術文書、UI文言は書く前に `SKILL.md` と該当する `references/` を読む。本人名義の文では `~/.nihongo/profile.md`（`[common]`/`[casual]`/`[work]`/`[formal]` と「絶対に言わない表現」）を使う（技術文書とAI返答には使わない）。敬語と硬さは相手と場面で先に決め、`[casual]` は `[formal]` に持ち込まず曖昧な時は安全な側へ倒す。口調を直された時か同じクセが2回出た時だけ末尾に1行で箱と追記内容を添えて確認し（黙って書かない・閲覧削除はいつでも可）、実名や連絡先などの個人情報は書かない。
6. **ユーザーの明示指示を優先する。** 具体的な指定や設定・他スキルと食い違う所はユーザー指定を優先する（ただし2の詐欺・なりすまし拒否は常に優先）。
